# Frozen two-clip experiment (19 October 2026)

This protocol extends the earlier single-clip experiment at the user's explicit request. It supersedes the old restriction to one final test for this extension only. Historical registries, predictions, references, configuration files, weights and results remain unchanged. Test clip 1 is the own clip, data/test/clip.mp4, already evaluated before this extension. Test clip 2 is the instructor's denmark_wales_clip_1min.mp4, copied without transcoding from new_video/ into data/test_2/. It is an additional holdout tested with methods already selected on SoccerNet validation. Neither test video nor its labels may be used for training, checkpoint selection or parameter tuning.

## Resolution and fixed metrics

Both clips have 1500 frames at 25 fps (60 seconds). Clip 1 is 1350x1080, with diagonal 1728.8435 pixels; clip 2 is 640x360, diagonal 734.3024 pixels. The existing primary rule is center distance <= 1% of each original image diagonal: 17.2884 pixels for clip 1, 7.3430 for clip 2. This retains the earlier criterion, not the earlier numerical pixel tolerance. Positions and errors remain in the original video coordinates. No resizing is introduced for classical inference or evaluation; NN preprocessing remains exactly as configured (960 selected, 1280 original).

Report mean and median pixel center error, mean center error divided by the corresponding image diagonal, the number of error samples and the number of visible frames without an accepted position. Also report the total explicit missing predictions over all 1500 frames. Normalized error is a fraction of the diagonal, not a percentage or an IoU. Raw pixel errors must not be compared alone. Diagonal normalization adjusts geometric scale but does not equalize ball size, aspect ratio, blur, camera framing or semantic difficulty. Classical kernels/area filters, pixel-based noise settings and NN input sizes stay unchanged; their effective scale relative to the ball may differ. Fractional association gates scale with image diagonal. These are transfer limitations, not grounds for post-test adjustments.

No new success threshold is introduced. Existing observed-only and capped normalized missing-penalty metrics remain secondary and are applied identically to both clips. The missing-penalty error averages min(distance/diagonal, 1) over visible frames, using 1 for an absent accepted position.

## Annotation and eligibility

Create a separate, initially unlabeled CSV for clip 2, stride 1, indices 0..1499, timestamps frame/25. No clip-1 annotation is imported. Draw or redraw a tight box only when the ball can be localized, including an identifiable blur or partial occlusion. Do not infer a hidden center. R confirms the current proposal; O marks occluded, U uncertain, F out_of_frame, and Q saves/exits. O/U/F save and advance. Pending-only startup resumes the first unreviewed frame. Orange/PENDING boxes are unapproved; approval is explicit. No model-generated proposals are supplied for this experiment. If interpolation is used by the annotator, every generated row remains unreviewed until individually confirmed; never interpolate across hidden/unknown positions.

After all frames are manually reviewed, generate a model-blind quality queue: first/last frame, both sides of every status transition, and a seeded random 10% of visible frames (ceil, seed 42). Confirm or correct these on the raw video. The quality gate checks timestamped manual audit events after queue creation and their final values. New boundaries caused by corrections are added before evaluation. This is a consistency check, not independent multi-annotator validation. Complete uncertain labels are valid reviewed decisions and remain excluded, rather than being guessed.

Tracking accepts observed and predicted outputs on visible frames. An accepted center within tolerance is TP. A wrong position is FP plus FN; a missing accepted position is FN. On occluded/out_of_frame frames, an observed output is FP; a predicted hidden position is counted separately and not scored as FP or a position error. This existing asymmetric policy can under-penalize false extrapolation and is disclosed. Uncertain frames contribute neither TP, FP, FN nor position errors. All 1500 frames still update temporal state and count in FPS. Observed-only suppresses predicted outputs on visible frames, with otherwise identical rules.

Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN). Empty precision/F1 denominators yield zero; recall without visible GT is undefined. Conditional center errors include every returned accepted position on eligible visible frames, including wrong positions; missing, invisible and uncertain rows have no measured center error. Lost periods are consecutive visible FN frames, split by invisible/uncertain frames; duration is frames/25. Per-frame CSVs list GT status, prediction status, correctness and center error; reference membership lists the exact uncertain exclusions.

## Speed, outputs and interpretation

Record hardware/software from each run.json. The existing machine records identify NVIDIA GeForce GTX 1070 for NN and an Intel64 Family 6 Model 94 Stepping 3 CPU. New clip-2 runs use two OpenCV threads and execute sequentially. Pipeline FPS includes camera motion, detection, CPU transfer/synchronization and association. It excludes decode, encode, drawing, model loading and one warm-up. End-to-end FPS includes decode, warm-up, pipeline, drawing, encoding and CSV write, but excludes model loading. GT visualizations and subsequent evaluation are excluded from both. Historical clip-1 timings were recorded in earlier sessions (original thread counts unknown); they are not a controlled same-session benchmark against clip 2. Different resolutions also affect throughput.

Clip-2 prediction-only videos and CSVs go to runs/two_clip_experiment/test_2/{selected,original}/{classical,nn}/. The combined table and separate per-clip outputs go to results/two_clip_experiment/completed/. Cyan-GT error-analysis videos are separate from inference videos. Preserve exact references and hashes. Report all four versions for both clips without pooling correlated frames into one headline result.

For visual analysis after evaluation, inspect the full GT videos and use a fixed initial example rule per method/clip: first correct visible output, first wrong visible output, first missing visible output, and first observed output during invisibility, when available. Compare small/localizable balls, motion blur, occlusion transitions, camera motion, shot cuts, player confusion and line confusion. Annotate evidence as frame/time, observed GT and prediction behavior, category and confidence; ambiguous categories remain unknown. Count a category only after explicit review, not from a plausible story. Do not assume better instructor-video quality or attribute performance differences solely to quality. Resolution, ball scale, editing, scene content, domain shift, visibility balance and annotation uncertainty may also differ; these remain hypotheses unless supported by inspected evidence. With two edited minutes, one annotator and one previously evaluated clip, generalization claims remain limited.
