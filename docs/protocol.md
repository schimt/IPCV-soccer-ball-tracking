# Evaluation and annotation protocol

Historical scope: this document records the original test-clip-1 protocol. The user-requested two-clip extension of 19 October 2026 is governed by [two_clip_protocol.md](two_clip_protocol.md), which supersedes the one-test-only restriction while retaining the existing scoring definitions. Clip 1 artifacts remain unchanged; clip 2 is separate and awaits manual review. References below to the sole/new test describe the earlier experiment.

Freeze the configuration, checkpoint and this protocol before opening the new test clip for model development. Annotation itself is allowed; changing methods using its appearance or errors is not. Use SoccerNet training games for fitting and a disjoint SoccerNet validation game for all parameter choices. The new test clip must come from another environment and is never placed inside a YOLO dataset.

All frame indices in project CSVs start at zero. Timestamps are frame / FPS in seconds. Input is assumed constant frame rate; transcode variable-frame-rate footage to a constant rate before annotation. Record original source, conversion, permission, resolution, FPS, duration and SHA256 in the report. The source clip should be 60 seconds; the final evaluation command can check duration. Preserve the clip after annotation so its hash remains stable.

The final-test annotation schedule is every frame: 0, 1, ..., 1499, exactly 1500 frames at 25 Hz (0.04 seconds apart). The last frame begins at 59.96 seconds. The completed 300 stride-5 labels and approvals are preserved; the other 1200 frames require manual review. `visible` means the ball can be localized; draw a tight axis-aligned box around the visible ball or its identifiable blur. `occluded` means it is hidden, `out_of_frame` means it is outside the image, and `uncertain` means localization/presence cannot reliably be decided. These three statuses must have empty geometry. `unlabeled` is unfinished work and evaluation rejects it. Mark a partially occluded but localizable ball visible; use a consistent tight visible-extent policy and document it. Do not infer hidden coordinates from motion.

The manual GUI saves each box as an unreviewed proposal. In pending-only mode, R confirms the box/status and advances to the next unreviewed frame; O/U/F save a visibility decision and advance. All navigation skips approved frames. Q saves and exits; startup resumes the first unreviewed frame. After the last approval it saves and closes automatically. Restored and interpolated proposals have reviewed=0. Human confirmation changes source to manual_review, preserving provenance in the before/after audit log. Final GT requires reviewed=1 and source manual or manual_review on all 1500 frames. Raw interpolated or assistant proposals are rejected even if their review flag is set. No label is automatically certified by expansion or interpolation. Annotate without model predictions; recheck visibility transitions and a random 10% of reviewed visible frames. Imported SoccerNet MOT and synthetic annotations remain development/software fixtures only.

The sole final test is now fixed to data/test/clip.mp4, source interval [0,60) seconds of the user-selected data/test/source_video.mp4, associated with https://www.youtube.com/watch?v=t0GESlaVNdE. It contains exactly 1500 frames at 25 FPS, 1350x1080. configs/final_test.json records the hashes, source interval and selection rationale. No alternative final test video may be added. Keep camera cuts, close-ups, audience shots, celebrations and the replay beginning; annotate visibility instead of removing inconvenient frames. Final results and presentation overlays must use this full clip for both methods. The fixed localization threshold evaluates to approximately 17.29 pixels at this resolution.

Primary correctness threshold: Euclidean center distance <= 0.01 times the image diagonal. At 1920x1080 this is about 22 pixels; it measures localization, not tight-box quality. Keep the threshold fixed for both methods. If a different threshold is justified on validation data, freeze it before testing. Report threshold and resolution together. This threshold is deliberately more tolerant than a ball-sized IoU criterion for tiny balls.

For a visible ball, a correct position gives TP. A missing position gives FN. A returned position outside the threshold gives both FP and FN. Precision=TP/(TP+FP), recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN). Visible-frame localization coverage equals recall in this single-ball setting. Empty denominators give zero precision/F1; recall is undefined if there are no visible frames.

Tracking metrics accept observed and predicted positions on visible frames. Observed-only metrics suppress extrapolated positions. On occluded/out-of-frame frames an observed detection is FP; an explicitly predicted hidden position is counted separately, without localization scoring or treating it as an observation. Uncertain frames are excluded from both positives and negatives and their number is reported. A predicted state has no fabricated confidence. The filter expires after 0.24 seconds by default.

Mean and median center error include every returned position on visible frames, even incorrect ones. They are conditional metrics, so report their sample count and recall alongside them. Normalized error divides by the image diagonal. A separate metric averages min(error/diagonal,1) over all visible frames, assigning penalty 1 to missing positions. This prevents a silent advantage for a method that rarely predicts.

A lost period is a consecutive run of visible reviewed frames without correct localization, with frame-index increment 1. Occluded, uncertain and out-of-frame frames break the run. Duration is failed frame count / 25 seconds, at 0.04-second resolution. Every recorded frame is assessed, but events between video frames remain unobserved. Neighboring frames are correlated; the single edited clip, replay content and annotation ambiguity limit generalization. Counts, errors, coverage and examples use the same completed 1500-row manual annotation set for both methods, excluding uncertain frames from metrics. Both prediction CSVs must contain all 1500 frames, including explicit missing states; incomplete predictions are rejected. Presentation overlays and FPS measurements cover the full clip. Method parameters and model weights remain unchanged during this final test; configuration and weight hashes at expansion are recorded in configs/final_test.json.

Pipeline FPS times camera-motion estimation, detection and association after one warm-up. NN CPU transfer completes GPU work before the timer stops. End-to-end FPS additionally includes decoding, warm-up, drawing, encoding and CSV writing; model loading is excluded. Timing is hardware/run dependent. Run methods sequentially with other intensive work idle for meaningful timing comparisons.

Outputs include paired metric tables, conditional error curves, success/failure coverage, lost intervals, the first three visible successes/failures per method, and per-method overlay videos. Inspect examples manually to categorize line confusion, player confusion, blur, occlusion, camera motion/cuts and reacquisition. Fixed-rule examples are reproducible but do not replace a broader error review.
